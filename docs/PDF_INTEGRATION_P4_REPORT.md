# P4 administration backend

Delivered admin-only `/api/admin/integrations` APIs for template intake, inventory/configuration listing, sanitized raster page access, draft copies, optimistic saves, diagnostic tests/downloads, confirmed publication and transactional activation, previous-version activation and enable/disable decisions. Existing PDF routes remain independent. The feature remains disabled by default.

Intake validates PDF content, plain filenames, 40 MiB input and fixed page selections. Originals are retained privately before inventory, including failed intake quarantine; unsuccessful originals are not published or exposed by any route. Parser diagnostics remain in successful inventories. Parsing, diagnostic rendering and page rasterization run in resource-limited Linux subprocesses (30-second wall, 20-second CPU, 512 MiB address space). No embedded actions execute. This bounds processing; it is not an operating-system security sandbox. Poppler is required for raster previews and is included in the container recipe.

Diagnostic PDFs remove widgets and remain visibly watermarked. Tests exercise every declared answer choice independently and retain all included pages for visual review. Publication requires complete dispositions, policies, explicit result groups, compatible sources, exact-hash test evidence, unchanged source schemas, explicit verified target IDs, a change summary and confirmation. Published records remain immutable. Mapping edits invalidate earlier tests by configuration hash. Unsupported normalized derivatives block publication until a verified renderer strategy is added; original per-occurrence overlays are supported.

Verification: eight admin API cases passed across SQLite and PostgreSQL, including real bounded intake/raster/render processing, direct non-admin rejection, incomplete drafts, stale revisions, immutable published data, retained old versions, bad time sources and stale test evidence. The earlier 42-case admin/domain/storage batch also passed. Compile and whitespace checks passed. Tests use synthetic PDFs only.

Remaining: P5 visual workspace, P6 technician details, and P7 final export lifecycle. No production templates are configured, no production deployment performed, and these diagnostic tests are not completed inspection exports. Failed intake originals require operator review; no automatic cleanup deletes originals.
