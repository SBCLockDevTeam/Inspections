# P6 technician Form Details and readiness

Completed October 29, 2026.

The authorized `/api/inspections/{id}/form-integrations` API exposes both integrations, published definitions, source status, saved additional values, explicit scope and structured readiness. Writes append decisions; they never modify existing inspection/checklist/point/event data. Scope choices are audited against the applicability policy hash. Input saves compare the expected published version and saved source fingerprint. SQLite immediate transactions and PostgreSQL row locks serialize competing additional decisions. Stale writes return conflicts instead of silently replacing another device's answer.

The collapsible Export Form Details section separates NFPA 72 and Compliance, with typed numeric/date/time/text/dropdown/Yes–No–NA fields, units, required/conditional explanations, source links, override reasons/badges and field-level blocker navigation. Panel data requires an explicitly saved scope; no first-panel default is introduced. Signatures and supplemental sheets have visible explanations. Export actions explain that completed preview/download handling remains P7; saved readiness is not permission to bypass that unfinished lifecycle.

Textbox/date/number values save on blur/Enter, choices save on change, and explicit field/form/global Save actions retry failed writes. Unsaved values, scope choices and override reasons remain private in memory through polling/navigation. Failed saves retain edits. Later edits made during an in-flight save retain their unsaved status. Refreshes discard responses after navigation and recover on visibility/connection changes. Changed published questions retain older saved decisions and expose review warnings; local drafts are explicitly archived before loading current definitions and can be downloaded for review. Signing out hides local drafts; a different authenticated user clears the previous user's in-memory private drafts.

Overrides must identify a distinct actual saved source, match its current value/fingerprint and include a reason. Changes to that source block readiness and require explicit revalidation. Zero, No and NA remain separate from missing. Manual per-panel answers remain bound to their panel. An unavailable integration is isolated from existing inspection entry and exports.

Integration review also moved complete diagnostic batches into the resource-limited worker, released database write locks during rendering, retained failed diagnostic states, scoped synthetic choices to relevant inputs, and allowed testing new manual definitions without adopting incompatible old answers. It completed private intake quarantine diagnostics (immutable `intake.json` beside originals), strict admin revision inputs and rejection of contradictory no-panel configurations. No database schema or legacy record changes were needed.

Verification includes SQLite and PostgreSQL tests for append-only decisions, typed validation, explicit/foreign/omitted scope, concurrent-session conflicts, current-source overrides, stale source detection, changed published questions, authorization/deletion and feature-off isolation.
